# Zine Exchange Club – Claude Guidelines

## General Principles
- **Think before coding** – surface assumptions, ask clarifying questions, break work into small pieces.
- **Simplicity first** – write the smallest vanilla PHP code that solves the problem; avoid unnecessary libraries or abstractions.
- **Surgical changes** – modify only the files directly related to the request; do not re‑format or refactor unrelated code.
- **Goal‑driven execution** – define a clear success criterion for each task and verify it (e.g., a passing test or updated email template).

## Language‑Specific Rules (PHP 8.3+)
- Enable strict types (`declare(strict_types=1);`).
- Use typed properties, parameter and return types.
- Prefer readonly classes, enums, and constructor property promotion where appropriate.
- Follow SOLID principles and keep a thin service layer; avoid heavy frameworks.
- Run PHPStan level 9 and maintain ≥ 80 % PHPUnit coverage for new code.

## Project Structure
- `config.php` – central place for DB credentials, SMTP settings, and constants.
- `includes/` – contains core logic such as `pairing_algorithms.php` and `email.php`.
- `admin/` – admin dashboard handling POST actions.
- `process.php` – user‑facing flow for confirming and reporting exchanges.
- `emails/` – PHP templates rendered by `renderEmailTemplate()`.

## Security & Sanitisation
- Always sanitise any data coming from `$_GET`, `$_POST` or email contents before using it.
- Never trust external SMTP responses; validate what is sent.
- Tokens stored in `cycle_participations.confirmation_token` must be verified against the DB and have an expiry check.

## Testing Guidance
- Write PHPUnit tests that cover happy‑path and error cases for any new functions.
- Add integration tests that hit the real database when the user explicitly requests end‑to‑end verification.

## Documentation
- Keep a high‑level `flow.md` that outlines the exchange cycle steps (registration, pairing, email flow, confirmation).
- Update this CLAUDE.md when new conventions are adopted.
